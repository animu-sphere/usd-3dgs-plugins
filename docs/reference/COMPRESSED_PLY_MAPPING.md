# Compressed PLY mapping contract

This is the normative mapping for the SuperSplat compressed PLY dialect of
the `gaussian-ply` bundle. It documents how a compressed `.ply` becomes the
format-independent [`GaussianCloudData`](GAUSSIAN_MODEL_CONTRACT.md) and what
the plugin authors. The Graphdeco dialect in the same bundle is documented in
[PLY_MAPPING.md](PLY_MAPPING.md); this document mirrors it and
[SPZ_MAPPING.md](SPZ_MAPPING.md) so the decoders can be read side by side.

No prose specification of the format exists. Every fact below comes from
MIT-licensed reference code: the writer and reader of
[SplatTransform](https://github.com/playcanvas/splat-transform) `v3.11.2`
(`write-compressed-ply.ts`, `compressed-chunk.ts`, `decompress-ply.ts`,
`read-ply.ts`) and the PlayCanvas engine's `gsplat-compressed-data.js`. The
[format spike](../reports/format-spike-compressed-ply-2026-11-17.md) records
the revisions read and the measurements that confirmed them. Where the two
reference readers differ, the choice made here is stated in §4.

## 1. Signature and routing

`CanRead()` claims a file from its header alone when the `vertex` element
declares `packed_position` **and** a `chunk` element exists
([DESIGN_POLICY.md §7.6](../design/DESIGN_POLICY.md#76-canread-contract)).
The Graphdeco signature (`scale_0`, `rot_0`, `opacity`, `f_dc_0`) cannot occur
in this layout, so the two dialects never claim the same file. A vertex
element with `packed_position` but no `chunk` element is neither dialect and
fails with `GSPLY-E001`, as before.

Both dialects stay in the `gaussian-ply` bundle because it owns the `.ply`
extension. `GaussianPlyDecoder` dispatches on the signature; the Graphdeco
path, its diagnostics, and its outputs are unchanged.

## 2. Container layout

| Element | Rows | Properties |
| --- | --- | --- |
| `chunk` | `ceil(N / 256)` | 18 `float`: `min_x min_y min_z max_x max_y max_z`, `min_scale_x min_scale_y min_scale_z max_scale_x max_scale_y max_scale_z`, `min_r min_g min_b max_r max_g max_b` |
| `vertex` | `N` | 4 `uint`: `packed_position packed_rotation packed_scale packed_color` |
| `sh` (optional) | `N` | `uchar f_rest_0 … f_rest_{R-1}`, `R` = 9, 24, or 45 for SH degree 1, 2, or 3 |

Vertex `i` uses chunk `floor(i / 256)`; the last chunk may be partial. No `sh`
element means degree 0. Properties are resolved by name, so declaration order
does not matter, but each element must declare exactly the properties above,
once each, with exactly those types. Element order is free.

| Input | Behavior |
| --- | --- |
| `format binary_little_endian 1.0` | supported; every observed producer writes it |
| `ascii` or `binary_big_endian` | rejected, `GSPLY-E020` |
| 12-property `chunk` (no colour bounds) | rejected as an unsupported variant, `GSPLY-E021`. SplatTransform's reader accepts it, but no producer of it has been observed. |
| Any other property set or type, a duplicate property, or an element other than `chunk`, `vertex`, `sh` | rejected, `GSPLY-E022` |
| `chunk` rows other than `ceil(N / 256)`, or `sh` rows other than `N` | rejected, `GSPLY-E023` |
| `N = 0` | rejected, `GSPLY-E002` |
| `N` above the shared import limit | rejected before allocation, `GSPLY-E019` |
| `sh` column count not divisible by 3, not a whole degree, or above degree 3 | `GSPLY-E008`, `GSPLY-E009`, `GSPLY-E017` |
| Non-finite chunk bound, or a minimum above its maximum | rejected, `GSPLY-E024` |
| Body shorter than the header declares | rejected, `GSPLY-E015` |

Trailing bytes after the last row are ignored, as for Graphdeco PLY. There is
no format version field; `comment Generated by …` names the producer and is
not interpreted.

## 3. Bit layout

`unorm(v, b) = (v & (2^b − 1)) / (2^b − 1)` and
`lerp(lo, hi, t) = lo · (1 − t) + hi · t`, evaluated in double precision with
the vertex's chunk bounds.

| Word | Bits |
| --- | --- |
| `packed_position`, `packed_scale` | x in bits 31–21 (11 bits), y in bits 20–11 (10 bits), z in bits 10–0 (11 bits) |
| `packed_rotation` | index of the dropped (largest) component in bits 31–30, then the other three in ascending component order as 10-bit values in bits 29–20, 19–10, 9–0 |
| `packed_color` | red bits 31–24, green 23–16, blue 15–8, alpha 7–0 |

## 4. Semantic conversion

For Gaussian `i` with chunk bounds `b`:

```text
position[i]  = lerp(b.min_xyz, b.max_xyz, unorm(packed_position))
scale[i]     = exp(lerp(b.min_scale_xyz, b.max_scale_xyz, unorm(packed_scale)))
rotation[i]  = normalize(q), where
                 s_k = (unorm(stored_k, 10) − 0.5) · √2   for the three stored
                 q[largest] = sqrt(max(0, 1 − s_0² − s_1² − s_2²))
                 the stored s_k fill the other slots of (rot_0, rot_1, rot_2, rot_3)
opacity[i]   = alpha / 255
dc[i]        = (lerp(b.min_rgb, b.max_rgb, rgb / 255) − 0.5) / SH_C0,
               SH_C0 = 0.28209479177387814
rest byte v  = −4 if v = 0;  +4 if v = 255;  otherwise (v + 0.5) / 32 − 4
```

`(rot_0, rot_1, rot_2, rot_3)` is the Graphdeco scalar-first `(w, x, y, z)`.
The writer makes the dropped component non-negative, so the square root
needs no sign. When the stored squares sum past 1, the reconstruction clamps
to zero rather than producing NaN. Normalization is part of the decode, so it
is not reported with `GSPLY-W001`.

Recorded choices where the reference readers differ:

- **Opacity.** SplatTransform's reader returns a logit, which is infinite at
  bytes 0 and 255; the engine clamps it to ±40. The model stores physical
  opacity, so `byte / 255` avoids both, and bytes 0 and 255 decode to exactly
  0 and 1.
- **SH rest.** SplatTransform decodes to the bucket centre; the engine uses
  `byte · 8 / 255 − 4`, which differs by up to about 1/64. The bucket centre
  matches the writer's `trunc((v / 8 + 0.5) · 256)` and gives the smaller
  error bound in §7.
- **Colour bounds** are used as stored. Real files carry bounds outside
  `[0, 1]` (observed from −0.49 to 2.61), so no unit range is assumed.

A scale whose `exp` leaves float range fails with `GSPLY-E012`. Every other
attribute is finite by construction once the chunk bounds are finite.

## 5. Coordinate frame

Compressed PLY stores the same raw Graphdeco **right-down-front** columns as
uncompressed PLY. After decoding, the shared `FlipYZAxes` converts the cloud
to the model's **RUB** frame ([ADR 0001](../adr/0001-model-frame-is-rub.md))
exactly as [PLY_MAPPING.md §3](PLY_MAPPING.md) describes. The import
statistics report `RdfToRub`.

## 6. Spherical-harmonic layout

`sh` columns are channel-major, like Graphdeco `f_rest_*`: column
`f_rest_{channel · C + k}` holds coefficient `k` of `channel`, with
`C = R / 3`. The decoder applies the same transpose as
[PLY_MAPPING.md §4](PLY_MAPPING.md) to reach coefficient-major RGB triples,
then the per-coefficient RDF→RUB sign table.

## 7. Quantization loss

The format quantizes every attribute. Half-step bounds, per chunk:

| Attribute | Bound |
| --- | --- |
| Position | `(max − min) / 4094` on x and z, `/ 2046` on y |
| Scale | relative `exp(range / 4094) − 1` on x and z, `exp(range / 2046) − 1` on y, where `range` is the log-scale span |
| Rotation | `√2 / 2046` per stored component; the reconstructed component amplifies it as it nears zero. The tests hold every component to the shared 8e-3 envelope ([EQUIVALENCE.md §2](EQUIVALENCE.md)). |
| Opacity | `1 / 510` |
| DC | `(max_c − min_c) / (510 · SH_C0)` |
| SH rest | `1 / 64` for bytes 1–254; up to `1 / 32` in the two end buckets, which decode to exactly ±4 |

Losses beyond quantization:

- The writer clamps log scales to `[−20, 20]` and SH rest values to `[−4, 4]`.
  Values outside those ranges saturate. A real SuperSplat file reaching the
  `−20` clamp was observed.
- SH degree is at most 3.
- The writer reorders Gaussians (Morton order), so source order is not
  preserved. The importer authors the file's order.

## 8. Metadata, statistics, and source format

- **Metadata-only reads** take `N` from the `vertex` element and the degree
  from the `sh` column count. They validate the whole header (§2) but read no
  rows, so body defects (`GSPLY-E012`, `GSPLY-E015`, `GSPLY-E024`) appear only
  on a full read.
- **Source format.** The stage records
  `customData.gs.sourceFormat = "Gaussian Splatting compressed PLY"`, and the
  import statistics report the same token with source version
  `binary_little_endian`. A distinct token tells consumers the arrays were
  decoded from a quantized source; uncompressed PLY keeps
  `"Gaussian Splatting PLY"`.
- **Import options** (`shDegree`, `opacityThreshold`, `scaleMultiplier`) apply
  to the decoded cloud exactly as for Graphdeco PLY.

## 9. Render-mode tags

SplatTransform and Brush tag the splat model in a header comment:
`SplatRenderMode: default | mip | 2dgs`, and Postshot writes
`postshot.anti_aliasing=0 | 1`. The decoder reads these tags as
SplatTransform does: case-insensitive, last match wins, unknown values
ignored. A non-default model (`mip`, which `anti_aliasing=1` also selects, or
`2dgs`) produces one warning, `GSPLY-W004`. The cloud is otherwise decoded and
authored unchanged, because the authored schema carries no render-mode
convention. This follows the SPZ antialiased flag (`GSPZ-W002`). The
Graphdeco dialect does not read these tags.

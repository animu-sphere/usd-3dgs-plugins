# Import limits

These are the default resource limits applied before the PLY, SPZ, SOG, or
`.splat` readers allocate unbounded source or model data. PLY covers both the
Graphdeco and the SuperSplat compressed dialects. They are an input-safety
policy, not a change to the `GaussianCloudData` model contract: the model has
no semantic Gaussian-count ceiling below what the platform can address.

The shared Gaussian ceiling is deliberately above the committed 5.8-million
Gaussian PLY performance asset, while keeping a declared count from turning a
single import into an unbounded allocation request.

| Resource | Limit | Applies to |
| --- | ---: | --- |
| Declared Gaussian count | 8,000,000 | PLY, SPZ, SOG, `.splat` (the count implied by the file size) |
| SOG `meta.json` size | 4 MiB | Bundled and unbundled SOG |
| SOG JSON nesting depth | 32 levels | SOG metadata |
| SOG JSON value tokens | 100,000 | SOG metadata |
| SOG v3 blind textures | 64 | SOG v3 `meta.json` `blind` entries; the planes are never decoded |
| SOG bundled archive source size | 1 GiB | Bundled SOG |
| SOG ZIP entries | 64 | Bundled SOG |
| SOG ZIP expanded size | 2 GiB | Bundled SOG |
| SOG ZIP entry / companion input size | 512 MiB | SOG planes |
| SOG decoded plane dimensions | 16,383 x 16,383 pixels | SOG WebP planes |
| SOG decoded RGBA plane size | 512 MiB | SOG WebP planes |
| SPZ source file size | 1 GiB | SPZ v1-v4 |
| SPZ extension records | 64 MiB | SPZ v1-v4 |

For bundled SOG, full and metadata-only reads check the declared expanded size
of `meta.json` before allocating its extraction buffer or inflating the entry.

The readers also use checked multiplication and allocation helpers for model
arrays, reject zero-count clouds, require every SOG plane to be present and
large enough for the declared count, reject duplicate SOG plane names and ZIP
entries, and retain the SPZ format's `INT32_MAX` representability check. The
unbundled SOG file-format loader applies the plane input bound to the
resolver-provided asset size before allocating a companion buffer; the reader
keeps the same check after the loader returns. The shared 8,000,000 count
ceiling is evaluated after those format-level range checks, so existing
malformed-container diagnostics remain stable. A `.splat` file has no declared
count: the reader derives it from the file size, after the signature and
record-size checks, so the largest accepted file is 256,000,000 bytes.

Limit failures use the format-specific stable diagnostic codes `GSPLY-E019`,
`GSPZ-E015`, `GSSOG-E016`, and `GSSPLAT-E004`. A failed import never produces a
partial `GaussianCloudData` or USD layer. `CanRead()` remains a routing
decision and may claim a structurally recognizable file whose `Read()` then
rejects a declared resource limit.

These budgets are compile-time defaults. Any host configuration of them must
preserve the same checked arithmetic and atomic import failure.

## Test coverage

Each budget is exercised by a committed fixture or a test-time input that is
small on disk and hostile only in what it declares. Fixtures are regenerated by
the bundle's `tools/generate_fixtures.py`; the reader unit tests assert the
diagnostic code and, where several budgets share one code, a fragment of the
message naming the budget that fired.

| Budget | Hostile input | Expected |
| --- | --- | --- |
| Declared Gaussian count | `gaussian-ply/.../too-many-gaussians.ply`, `gaussian-ply/.../compressed-too-many-gaussians.ply` (header only; full and metadata-only reads), `gaussian-spz/.../shared-limit-v2.spz`, `gaussian-spz/.../shared-limit-v4.spz` (header only; full and metadata-only reads), `gaussian-sog/.../too-many-gaussians/meta.json`, a `.splat` file grown to 8,000,001 records at test time (reader `TestImportLimit`; full and layout-only reads) | `GSPLY-E019`, `GSPZ-E015`, `GSSOG-E016`, `GSSPLAT-E004` |
| SOG `meta.json` size | `zip-metadata-over-limit.sog` declares 4 MiB + 1 byte; unbundled `meta.json` of the same size, written at test time | `GSSOG-E016` (full and metadata-only reads) |
| SOG JSON nesting depth / value tokens | in-memory documents one past each bound | `ParseJson` rejection (`GSSOG-E005` when reached through `meta.json`) |
| SOG ZIP entries | `too-many-entries.sog` (65 entries) | `GSSOG-E016` |
| SOG v3 blind textures | `v3-too-many-blind.sog` (65 `blind` entries) | `GSSOG-E016` |
| SOG ZIP entry size | `oversized-entry.sog` (one entry declaring 600 MiB) | `GSSOG-E016` |
| SOG ZIP expanded size | `oversized-expansion.sog` (five entries declaring 500 MiB each) | `GSSOG-E016` (full and metadata-only reads) |
| SOG duplicate ZIP entry | `duplicate-entry.sog` | `GSSOG-E004` |
| SOG duplicate plane name | `duplicate-plane-name.sog` | `GSSOG-E005` |
| SOG plane dimensions | `oversized-plane-dimensions.sog` (header declares 16,384 x 1) | `GSSOG-E016` |
| SOG decoded RGBA plane size | `oversized-plane-bytes.sog` (header declares 16,383 x 16,383) | `GSSOG-E016` |
| SPZ extension records | `oversized-extensions-v2.spz` (64 MiB + 1 byte of zeros, ~64 KiB compressed) | `GSPZ-E015` |
| SPZ v4 extension zone | `.spz` whose v4 header places the TOC 64 MiB + 1 byte after the header, grown to hold it at test time (reader `TestOversizedV4ExtensionZone`) | `GSPZ-E015` (full and header-only reads) |
| SOG bundled archive source size | `.sog` grown to 1 GiB + 1 byte at test time (reader `TestOversizedBundledArchive`) | `GSSOG-E016` (full and metadata-only reads) |
| SPZ source file size | `.spz` grown to 1 GiB + 1 byte at test time (reader `TestOversizedSource`) | `GSPZ-E015` (full and header-only reads) |
| SOG companion input size, directory loader | `quats.webp` grown to 512 MiB + 1 byte at test time (reader `TestOversizedUnbundledCompanion`) | `GSSOG-E016`; the metadata-only read still succeeds |
| SOG companion input size, asset resolver | same, opened through `ArDefaultResolver` (`test_gaussian_sog_resolver.py` `case_oversized_companion`) | `GSSOG-E016` |

Full and metadata-only reads also accept bundled metadata at exactly 4 MiB and
archives with exactly 64 entries.

The real-size rows grow a small file with `resize_file` / `truncate`, which
leaves the tail unwritten (a sparse hole on Linux and macOS, an unwritten
extension on NTFS). Nothing is committed, and each reader refuses the file
from its size before the bulk read, so the tests neither write nor allocate
the bytes. The reader's own re-check of a buffer that an injected companion
loader has already returned is not exercised: reaching it needs a real
512 MiB allocation.

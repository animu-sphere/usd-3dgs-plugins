# OST dogfooding report #4 -- v0.22.10 macOS CI failure from an empty optional-flag array

- Date: 2026-09-15
- OST: 0.22.10, release tag `v0.22.10`
- Host: GitHub-hosted `macos-15`, arm64, `/bin/bash`
- Runtime: OpenUSD 26.08 `metal` leaf, `cy2026` / `usd`
- Repository: `usd-3dgs-plugins`, PR [#33](https://github.com/animu-sphere/usd-3dgs-plugins/pull/33)
- Failing run: [34980650312](https://github.com/animu-sphere/usd-3dgs-plugins/actions/runs/34980650312)
- Failing jobs: [gaussian-ply macOS](https://github.com/animu-sphere/usd-3dgs-plugins/actions/runs/34980650312/job/104419772383), [gaussian-spz macOS](https://github.com/animu-sphere/usd-3dgs-plugins/actions/runs/34980650312/job/104419772337), [gaussian-sog macOS](https://github.com/animu-sphere/usd-3dgs-plugins/actions/runs/34980650312/job/104419772171)

## TL;DR

**This was an OST workflow-generator portability defect, not a USD runtime or
artifact defect.** With a valid source cell that omitted the optional
`require_openusd` and `require_openusd_version` fields, OST v0.22.10 generated
an empty Bash array and expanded it under `set -u`:

```bash
set -euo pipefail
openusd_args=()
ost artifact pull ... "${openusd_args[@]}" --json
```

The macOS jobs stopped with:

```text
openusd_args[@]: unbound variable
```

The failure happened before `ost artifact pull` contacted the pinned OCI
runtime. All six Windows/Linux jobs in the same run passed the corresponding
stage, and the three macOS jobs failed at the same generated line.

## What was observed

The PR updated the bootstrap from OST 0.22.8 to 0.22.10 and regenerated
[`.github/workflows/ost-source-ci.yml`](../../.github/workflows/ost-source-ci.yml).
The v0.22.10 generator added the optional OpenUSD matrix fields but emitted
empty values because the source cells did not declare them:

```yaml
require_openusd: ""
require_openusd_version: ""
openusd_flags: ""
```

The generated runtime-pull step then contained the empty-array expansion. The
three failing job logs show the same sequence: both optional values are empty,
the remote pull command is rendered, and Bash exits before invoking `ost`.

The failure is independent of the runtime digest. The macOS job used the same
26.08 runtime family as the passing Windows and Linux jobs, and it failed at
shell expansion before the artifact command could validate or download any
bytes.

## Minimal reproduction

On the affected macOS shell semantics, this shape is enough to reproduce the
failure:

```bash
set -euo pipefail
openusd_args=()
printf '%s\n' "${openusd_args[@]}"
```

An empty array expansion under `nounset` is not a portable way to represent an
optional argument list across the Bash versions used by the hosted runners.
The generated command compounded that by placing the expansion unconditionally
in both the cache-hit verification and remote-pull paths.

The relevant generator behavior is in the OST v0.22.10
[`ost-ci` GitHub renderer](https://github.com/animu-sphere/open-strata/blob/v0.22.10/crates/ost-ci/src/github.rs).
The release source owns the template that creates `openusd_args=()` and emits
`"${openusd_args[@]}"` without guarding the empty case.

## Diagnosis

The evidence separates the layers:

1. The failure is macOS-only within one matrix run: 3 failures and 6 passes.
2. All three failures have the same shell error and the same workflow step.
3. The error occurs before `ost artifact pull`, so the OCI reference and
   artifact digest are not implicated.
4. The generated workflow came from OST v0.22.10, and its source template
   permits the optional fields to be absent while still rendering an unsafe
   shell expansion.

Therefore the defect is in the OST GitHub workflow generator's handling of an
empty optional argument list. The repository manifest was structurally valid;
its omission of optional OpenUSD identity fields exposed the generator bug.

## Repository-side correction

The pinned runtime leaves are known OpenUSD 26.08 imaging leaves, so every
source cell now declares the identity it consumes in
[`openstrata.ci.yaml`](../../openstrata.ci.yaml):

- Windows: `cy2026/windows/x86_64/gl`
- macOS arm64: `cy2026/macos/arm64/metal`
- Linux: `cy2026/linux/x86_64/gl`
- Version: `26.08`

The workflow was regenerated with `ost ci generate github --force`. The
resulting matrix no longer has empty OpenUSD values, and the generated array
contains real arguments on every cell. This is both a valid runtime contract
and a reproducible workaround: a future regeneration keeps the source of
truth in the manifest instead of relying on a hand-edited workflow.

Checks completed locally after the correction:

- `ost ci validate`: 9 cells, structure OK
- Generated workflow contains the selector and version for every cell
- `git diff --check`: passed

## Suggested upstream fix

The generator should remain safe when optional OpenUSD requirements are absent.
Suitable implementations include rendering one pre-composed
`matrix.openusd_flags` string, or guarding every array expansion with an
array-length test before using `set -u`. The generated workflow should be
valid for the default Bash on every supported hosted runner even when a
manifest legitimately omits optional fields.

This repository-side correction does not claim that the upstream generator
itself is fixed. A later OST release should be tested by removing the explicit
selectors in a disposable matrix and regenerating the workflow; the empty
optional case should then be safe on macOS before the workaround is removed.

## Follow-up

The post-correction GitHub Actions run is the final hosted confirmation. The

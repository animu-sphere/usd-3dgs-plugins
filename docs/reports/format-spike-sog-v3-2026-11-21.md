# Format spike: SOG version 3 — 2026-11-21

This is the FMT-16 evaluation in [current work](../roadmap/current.md).
It records what was observed on 2026-11-21 against the named upstream
revisions and pages. It is not a support claim. The
[capability matrix](../reference/CAPABILITY_MATRIX.md) lists SOG v2 only,
and `gaussian-sog` rejects `version: 3` with `GSSOG-E003`.

## Summary

| Check | Result |
| --- | --- |
| Specification | The PlayCanvas developer site publishes SOG v3 as "the format specification", with a v2-to-v3 change table. SOG v2 has its own page (§1, §2). |
| Changes from v2 | Rotation becomes a 24-bit exponential map in `quats.webp` RGB. Opacity becomes `(a / 204)²`, reaching 1.5625. SH may have 4 bands. The SH palette may exceed 65,536 entries, with 24-bit labels. Optional blind textures, `extras`, and `comments` are added. Positions, scales, DC colour, the palette layout, and bundling are unchanged (§2). |
| Writers | SplatTransform writes v3 by default since 3.11.0 (released 2026-11-10); `--sog-version 2` still writes v2. 3.11.0 and 3.11.1 wrote an interim v3 layout with the rotation in alpha channels and no `quats.webp`. 3.11.2 (2026-11-12) moved it to `quats.webp` without changing the version number (§3). |
| Coordinate frame | Unchanged: Graphdeco PLY frame, converted with the shared `FlipYZAxes` (§4). |
| Model fit | Positions, scales, rotations, DC, and SH up to 3 bands fit the shared model. Opacity above 1 and a 4th SH band do not (§5). |
| Routing | Bundled `.sog` routing is unchanged. The unbundled `meta.json` gate must accept version 3, and must still route the interim layout so `Read()` can explain it (§6). |
| Fixtures | No v3 file is committed upstream. Deterministic v3 fixtures can be generated by extending `tools/generate_fixtures.py`. A v3 corpus conversion needs SplatTransform ≥ 3.11.2, which this environment cannot run (§7). |
| Dependency and package cost | None. Lossless WebP through the vendored libwebp and ZIP through miniz, as for v2 (§8). |
| Recommendation | Keep SOG v3 as the v0.13.0 format. No blocker was found. The format is 12 days old and has already changed once without a version bump, so FMT-17 pins the observed revisions and re-checks them before merge and before tagging. Scope and the five decisions it needs are in §9. |

## 2. Changes from v2

The specification's change table (§8 of the page) lists these, and states
that "everything else (positions, scales, DC color, the SH palette layout,
indexing and bundling) is unchanged":

| Area | v2 (implemented) | v3 |
| --- | --- | --- |
| Rotation | `quats.webp` RGBA, smallest-three: three 8-bit components in `[−√2/2, +√2/2]` and the dropped-component tag `252 + i` in alpha | `quats.webp` RGB, 24-bit exponential map; alpha unused (written 255) |
| Opacity | `sh0.a / 255`, at most 1 | `(sh0.a / 204)²`, 0 to 1.5625; `meta.opacity.max` present when some value exceeds 1 |
| SH bands | 1-3 | 1-4 (24 AC coefficients per channel at 4 bands) |
| SH palette | at most 65,536 entries; 16-bit labels in R, G | at most 2^24 entries (writers "should" keep it at or below 262,144); 24-bit labels `r + (g << 8) + (b << 16)` |
| Blind data | — | optional `blind_<i>.webp` RGBA planes described by `meta.blind[]`, each a list of typed fields (`u8`-`u32`, `f16`, `f32`, `unorm8`, `unorm16`) packed little-endian |
| Extras, comments | — | optional `extras` (application JSON) and `comments` (string array) |

`model` (`"antialiased"` or `"2dgs"`) exists in both versions. The v3
page also states that decoded colours are sRGB and display-referred; that
describes the same DC values and changes no arithmetic.

### Decode equations

Quoted from `quat-expmap.ts` and `opacity.ts` at `5d5be2b`; the
specification gives the same equations.

```text
p  = ((r − 128) / 127, (g − 128) / 127, (b − 128) / 127)
θ  = (π / 2) · |p|
q  = (cos θ, p · sin θ / |p|)          (w, x, y, z); identity when |p| = 0
A  = (sh0.a / 204)²                    byte 204 is exactly 1, byte 255 is 1.5625
```

- Bytes `(128, 128, 128)` are the exact identity. Readers "must accept any
  byte combination": rounding can make `|p|` slightly exceed 1 and the
  result is still a unit quaternion.
- The encoder flips the sign so `w ≥ 0` and rounds `p · 127 + 128`. Its
  measured error over 2 million random rotations is 1.20° maximum and 0.62°
  RMS, against 2.03° and 0.71° for v2.
- The opacity encoder is `min(255, round(204 · √A))`, with `A ≤ 0` stored as 0.
  The spacing between codes grows with the code, from 2.4e-5 at byte 0 to
  1.2e-2 at byte 255; it is 9.8e-3 at byte 204.

## 3. Writers

| Writer | Writes v3 | Notes |
| --- | --- | --- |
| SplatTransform ≥ 3.11.2 | by default | `--sog-version <2\|3>`, "Default: 3". v2 output drops opacity above 1, blind data, and a 4th band with a warning. Latest is 3.12.0 (2026-11-19), which only changes how the SH palette is sized. |
| SplatTransform 3.11.0-3.11.1 | by default, **interim layout** | PR #370: "Rotations are 24-bit exp maps in the alpha channels, so there is no `quats.webp`." PR #379 says the alpha bytes sat in `means_l`, `means_u`, and `scales`, and moved them because the RGB of those planes could be lost under a non-opaque alpha. The version number stayed 3. The current reader has no branch for the interim layout: a file without `meta.quats` throws. |
| SuperSplat | presumably, through SplatTransform | It depended on SplatTransform 3.11.2 on 2026-11-17. Whether its SOG export uses the library default was not checked. |

PR #370 calls v3 "the default output" and lists it under breaking changes:
v3 "needs a viewer with v3 support". PR #379 was held until a PlayCanvas
engine change (`playcanvas/engine#10007`) shipped in a viewer release,
because supersplat-viewer 1.43.0 "does not read `quats.webp` for v3".

The SplatTransform reader accepts versions 2 and 3, and a legacy v1 file
(no `version`). The v3 specification says readers "must check `version`" and
"should reject versions they do not support"; the v2 page says v2 "is still
read by all PlayCanvas tools". `gaussian-sog` keeps v2 support.

## 4. Coordinate frame

Unchanged from v2. Both specification pages say SOG stores Gaussians in the
3DGS PLY frame, and SplatTransform bakes to and reports `Transform.PLY` in
both versions. The decoder applies the shared `FlipYZAxes` to positions and
rotations as for v2
([SOG_FORMAT.md §6](../reference/SOG_FORMAT.md#6-format-decisions)). The
exponential map decodes to a quaternion in the file frame before the
conversion, exactly where the smallest-three unpacking sits today.

## 5. Fit with the shared model

| v3 content | Model rule | Consequence |
| --- | --- | --- |
| Exp-map rotation | unit quaternion through `NormalizeQuaternion` | fits |
| Opacity up to 1.5625 | opacity in `[0, 1]` ([model contract](../reference/GAUSSIAN_MODEL_CONTRACT.md)) | does not fit. The specification gives a renderer profile for values above 1 and says a renderer without that support "must clamp A to 1". |
| 4 SH bands | degrees 0-3; a higher declared degree is rejected, not truncated ([model contract](../reference/GAUSSIAN_MODEL_CONTRACT.md#supported-sh-degrees)) | rejected with `GSSOG-E007`, as a v2 `bands` above 3 is today |
| Palette above 65,536, 24-bit labels | no model limit; memory is bounded by the plane checks | fits. The centroid plane is `64 · coeffs` wide and `ceil(count / 64)` high, so the existing 16,383-pixel dimension limit caps the palette at 1,048,512 entries. |
| Blind fields | no per-Gaussian slot for arbitrary fields | not representable |
| `extras`, `comments` | no slot | not representable; application data, like the unknown fields readers are told to ignore |
| `model` | no slot | the v2 reader ignores it silently today, unlike PLY (`GSPLY-W004`) and SPZ (`GSPZ-W002`) |

## 6. Routing

- **Bundled `.sog`.** Unchanged: `.sog` extension and the ZIP local-file
  signature; everything else is validated in `Read()`.
- **Unbundled `meta.json`.** `CanRead()` claims a `.json` file only when it
  parses with `version == 2` and `means`, `scales`, `quats`, and `sh0` each
  carry a `files` array (`SogReader::CanReadUnbundled`). The gate must accept
  `version == 3`. An interim 3.11.0-3.11.1 `meta.json` has no `quats`, so the
  gate would refuse it silently, and the user would see only that no file
  format claimed the file. The v3 gate should therefore require `means`,
  `scales`, and `sh0`, and leave a missing `quats` to `Read()`, which can name
  the interim layout. The four keys stay required for v2. Three SOG-specific
  keys with `files` arrays still keep unrelated JSON out.

### New hostile-input surface

The existing bounds already cover most of v3: metadata size (4 MiB), ZIP
entry count (64) and expanded size, per-plane dimension (16,383) and decoded
bytes, the shared Gaussian limit (`GSSOG-E016`), and `count ≤ W·H` for every
per-Gaussian plane. v3 adds these inputs, each to be validated before any
allocation it sizes:

| Input | Check |
| --- | --- |
| `shN.count` up to 2^24 | the centroid plane must hold `ceil(count / 64)` rows of `64 · coeffs` texels, inside the plane limits; labels at or above `count` keep `GSSOG-W001` |
| 24-bit labels | read only for v3; v2 keeps ignoring the blue byte |
| `opacity.max` | if present, a finite number in `(1, 1.5625]`; it is informational, since the bytes already carry the value |
| `blind[]` | bounded entry count; each `files` entry passes the existing plane-name checks, and the plane is never decoded if blind data is ignored (D4) |
| `extras`, `comments` | parsed as JSON within the existing 4 MiB metadata limit and otherwise unused |
| Missing `quats` with `version: 3` | the interim layout, refused before any plane is decoded (D3) |

## 7. Fixtures

- **Upstream.** `test/sog-v3.test.mjs` generates its data in memory; no
  `.sog` or `meta.json` file is committed. It contains no hard-coded
  exp-map byte vectors, but asserts the opacity anchors: byte 0 → 0,
  204 → 1, 255 → 1.5625, and `encodeOpacityByte(1) == 204`. The
  specification gives one rotation example, `(0, 1/√2, 1/√2, 0)` →
  `(218, 218, 128)`.
- **Deterministic fixtures.** `plugins/gaussian-sog/tools/generate_fixtures.py`
  already writes lossless WebP planes and both layouts. A v3 encoder needs
  the exp-map, square-root opacity, 24-bit label, and blind-plane encodings
  above, all small. Hand-checked cases: identity, the specification's example,
  opacity bytes 0/204/255, a palette above 65,536 entries, and one fixture
  each for the interim layout, 4 bands, opacity above 1, blind data, and
  `model`.
- **`version-3.sog`.** Today it is the unsupported-version negative fixture.
  It becomes a `version-4.sog` that keeps `GSSOG-E003` covered; the existing
  `huge-version.sog` stays.
- **Equivalence.** The shared models can be encoded as v3 by the same tool
  and paired with lossless PLY in `gaussian_ply_sog_equivalence`, with a
  rotation tolerance from the exp-map step and an opacity tolerance of half
  the code spacing at the value.
- **Real assets.** No redistributable v3 file was found. Converting the
  committed CC0 corpus (`yashica-t4`, `leica-sofort`) with SplatTransform
  3.12.0 gives provenance-recorded v3 assets, as v3.1.6 did for v2. This
  environment does not allow installing or running SplatTransform, so the
  maintainer would run the conversion, for example
  `npx @playcanvas/splat-transform@3.12.0 <source>.ply <name>.sog`.

## 8. Dependency and package cost

None. v3 planes are still lossless WebP (SplatTransform encodes with libwebp
compiled to WebAssembly; no AVIF, KTX2, or Zstandard appears in the SOG
reader or writer). The vendored libwebp 1.6.0 decoder and miniz 3.0.2 cover
it, and the bundle's library size should change only by the new decode code.

## 9. Proposed scope for FMT-17 and FMT-18

FMT-17 adds v3 decoding to `SogReader` and `GaussianSogDecoder`, keeping v2
behaviour and diagnostics unchanged:

1. Accept `version` 2 and 3; reject anything else with `GSSOG-E003`.
2. Decode v3 rotations by the exponential map, then `NormalizeQuaternion` and
   `FlipYZAxes`; ignore the `quats` alpha byte.
3. Decode v3 opacity as `(a / 204)²`.
4. Read 24-bit labels and allow palettes above 65,536 within the plane
   limits; out-of-range labels keep `GSSOG-W001`.
5. Route v3 `meta.json` as in §6.
6. Fixtures, equivalence entries, diagnostics catalog, and references as in
   §7, and the SOG v3 rows PERF-01 needs.

FMT-18 declares the v3 fixtures in the bundle manifest and the aggregate
package consumer test, and updates the capability matrix and CHANGELOG.

Decisions for the maintainer. On 2026-11-21 the maintainer accepted every
recommendation below (D1-D5).

| # | Question | Recommendation | Alternative |
| --- | --- | --- | --- |
| D1 | Opacity above 1 | Clamp to 1 with a new warning, as the specification requires of a renderer without over-unity support. The authored opacity stays within the model contract. | Reject the file, or widen the model contract (a cross-format change). |
| D2 | 4 SH bands | Reject with `GSSOG-E007`, as the model contract requires. SplatTransform writes a 4th band only when its source has one. | Truncate to 3 bands with a warning, which the model contract currently forbids. |
| D3 | Interim 3.11.0-3.11.1 layout | Reject with `GSSOG-E003`, naming the layout and asking for a re-export with SplatTransform 3.11.2 or later. The layout lived two days, its byte mapping is not specified, and the reference reader no longer reads it. | Decode it from the PR #379 diff. |
| D4 | Blind textures | Ignore them with one new warning, because data present in the file is not imported. Ignore `extras` and `comments` silently. | Ignore all three silently. |
| D5 | `model` | Warn for `antialiased` and `2dgs` in both versions, matching `GSPLY-W004` and `GSPZ-W002`. This adds a warning to v2 imports that are silent today, so the FMT-17 exit criterion would list it. | Warn for v3 only, or keep ignoring it. |

Risk: v3 changed layout once within the same version number, and viewer
support was still landing on 2026-11-12. FMT-17 records the specification
read date and SplatTransform `v3.12.0` (`5d5be2b`) as its reference, and
re-reads both before the implementation merges and again before tagging. If
the layout changes again, re-evaluate the release scope before tagging.

Streamed SOG stays in the [backlog](../roadmap/backlog.md#other-format-candidates).
Its chunks may be v2 or v3 unbundled datasets, so v3 support is a
prerequisite there, not a change of its boundary.

## 10. Not verified in this spike

- The PR #379 diff, and so the exact plane and byte order of the interim
  layout. D3 does not need it.
- Whether SuperSplat's SOG export uses SplatTransform's default version.
- The PlayCanvas engine's v3 reader (`playcanvas/engine#10007`) and the
  developer-site change (#1336).
- SplatTransform's `sog-blind.ts` encodings beyond the specification text,
  and `SH_REST_COUNTS` in `src/lib/chunk/layout.ts`.
- Any SOG v3 file from a writer other than SplatTransform.

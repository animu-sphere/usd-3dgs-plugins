# Format spike: SuperSplat compressed PLY — 2026-11-17

This is the FMT-01 evaluation in [current work](../roadmap/current.md).
It records what was observed on 2026-11-17 against the named upstream
revisions and files. It is not a support claim. The
[capability matrix](../reference/CAPABILITY_MATRIX.md) still lists compressed
PLY as unsupported (`GSPLY-E001`).

## Summary

| Check | Result |
| --- | --- |
| Specification | Independently implementable from MIT reference code. The writer and reader of record agree on every fact below. No prose specification exists. |
| Format signature | Structural, from the header alone, and disjoint from the Graphdeco signature (§3). |
| Attribute fidelity | Every model attribute is recoverable, within quantization bounds derived from the encoding (§4). Measured errors on two real conversions stay at or below those bounds (§5). |
| Coordinate frame | Same raw frame as Graphdeco PLY (RDF). The shared `FlipYZAxes` applies, as it does for PLY and SOG. |
| Fixtures | Redistributable CC0 conversions of the committed corpus can be generated reproducibly. Third-party SuperSplat files were checked locally but carry no redistribution licence. |
| Dependency cost | None. The vendored tinyply already parses the container. No new production dependency, ADR, or notice entry. |
| Recommendation for FMT-02 | Select it for v0.10.0, scoped as in §7. |

## 2. Container layout

All files observed are `format binary_little_endian 1.0`. The upstream reader
requires that format for this layout. The header declares three elements in
this order, and the body stores their rows in the same order:

| Element | Rows | Properties |
| --- | --- | --- |
| `chunk` | `ceil(N / 256)` | 18 `float`: `min_x min_y min_z max_x max_y max_z`, `min_scale_x … max_scale_z`, `min_r min_g min_b max_r max_g max_b` |
| `vertex` | `N` | 4 `uint`: `packed_position packed_rotation packed_scale packed_color` |
| `sh` (optional) | `N` | `uchar f_rest_0 … f_rest_{3C-1}`, with `C` = 3, 8, or 15 for SH degree 1, 2, or 3 |

- Vertex `i` uses chunk `floor(i / 256)`. The last chunk may be partial. The
  writer pads it only for computing bounds and writes exactly `N` vertex rows.
- No `sh` element means degree 0. The writer refuses degree 4.
- There is no format version field. `comment Generated by …` names the
  producer. `comment SplatRenderMode: mip | 2dgs` records the render mode.
- The upstream reader also accepts a 12-property `chunk` without colour
  bounds. In that case colour is the raw unorm value. No producer of that
  variant was observed (§6).

## 3. Format signature and routing

Proposed `CanRead()` widening: this uses the header only, as
[DESIGN_POLICY.md §7.6](../design/DESIGN_POLICY.md#76-canread-contract) requires.

- Claim the file when a `vertex` element declares `packed_position` and a
  `chunk` element is present. The Graphdeco signature (`scale_0`, `rot_0`,
  `opacity`, `f_dc_0`) cannot appear in this layout, so the two dialects never
  claim the same file.
- `Read()` validates the rest with specific diagnostics: property names and
  types, the chunk row count, the `sh` column count and row count, binary
  little-endian, and body size.

Routing stays inside `gaussian-ply`, because the bundle owns the `.ply`
extension. The negative fixture `mesh-not-gaussian.ply` shows that
`Usd.Stage.Open` reaches `Read()` even when `CanRead()` is false. Today a
compressed file therefore fails with `GSPLY-E001`, as the capability matrix
states. Adding the dialect changes that one outcome and leaves ordinary mesh
and point-cloud rejection unchanged.

`PlyReader` currently models only the `vertex` element. The dialect needs a
header model that exposes `chunk` and `sh` as well. tinyply already supports
this.

## 4. Mapping to `GaussianCloudData`

`unorm(v, b) = (v & (2^b − 1)) / (2^b − 1)`. `lerp` uses the vertex's chunk
bounds.

| Model attribute | Encoding | Decode | Quantization bound (half step) |
| --- | --- | --- | --- |
| Position | 11/10/11 bits in x/y/z order, from bit 31 down | `lerp(min, max, unorm)` | `(max − min) / 4094` for x and z, `/ 2046` for y, per chunk |
| Scale | 11/10/11, log space; the writer clamps bounds to `[−20, 20]` | `exp(lerp(min_scale, max_scale, unorm))` | relative `exp(range / 4094) − 1` for x and z, `/ 2046` for y |
| Rotation | 2-bit index of the largest component (bits 31–30), then the other three in ascending index order as 10-bit unorm | `(u − 0.5) · √2`. The dropped component is `sqrt(max(0, 1 − a² − b² − c²))`, non-negative because the writer canonicalizes the sign. Normalize with `NormalizeQuaternion`. | `√2 / 2046` per stored component |
| Opacity | Alpha byte, bits 7–0, post-sigmoid | `byte / 255`. Already in `[0, 1]`; no logit round trip. | `1 / 510` |
| DC | RGB bytes, bits 31–8, as `f_dc · SH_C0 + 0.5` normalized to the chunk colour bounds | `(lerp(min_c, max_c, byte / 255) − 0.5) / SH_C0` | `(max_c − min_c) / (510 · SH_C0)` |
| SH rest | `trunc((v / 8 + 0.5) · 256)` clamped to `[0, 255]`, channel-major `f_rest_{channel · C + k}` | `0 → −4`, `255 → +4`, otherwise `(byte + 0.5) / 32 − 4`. Then the Graphdeco channel-major to Gaussian-major transpose that the PLY decoder already performs. | `1 / 64` inside `(−4, 4)`; values outside saturate |
| Frame | Graphdeco RDF, the same raw columns as PLY | shared `FlipYZAxes` on positions, quaternions, and SH | — |

Choices recorded for the importer:

- **Opacity.** The upstream reader decodes a byte through a logit, which
  gives `±∞` at bytes 0 and 255. The engine clamps to `±40`. The model stores
  physical opacity, so `byte / 255` sidesteps both, and 255 becomes exactly
  1.0.
- **SH rest.** SplatTransform decodes to the bucket centre. The engine uses
  `byte · 8 / 255 − 4`, which differs by up to about 1/64. The bucket centre
  matches the writer's truncation and gives the measured `1 / 64` bound (§5).
- **Losses to state in the mapping doc.** The format quantizes every
  attribute. Log-scales outside `[−20, 20]` saturate; this was observed in a
  real file (§6). SH rest outside `[−4, 4)` saturates. Degree is capped at 3.
  The writer reorders splats, so source order is not preserved (§5).

## 5. Round-trip evidence

Method: the committed CC0 corpus PLYs
(`plugins/gaussian-ply/tests/corpus/{yashica-t4,leica-sofort}`, Brush, SH
degree 3, 8,192 Gaussians each) were converted with
`@playcanvas/splat-transform@3.11.2`, using
`splat-transform <name>-top8192.ply <name>-top8192.compressed.ply`. They were
then decoded per §4 by an independent NumPy implementation and compared with
the source. The comparison used physical model units: `exp` scales, sigmoid
opacity, and normalized quaternions. Because the writer reorders splats
(Morton order), rows were matched by nearest position with an attribute
tie-break. The match was a bijection on both assets (8,192 unique rows). The
frame was compared without any flip.

| Measured maximum error | yashica-t4 | leica-sofort |
| --- | --- | --- |
| Position, absolute (scene extent ≈ 26 / 31 units) | 0.0100 | 0.0132 |
| Scale, relative | 0.77 % | 0.78 % |
| Rotation, angle | 0.198° | 0.217° |
| Opacity, absolute | 0.00196 (= 1/510) | 0.00196 |
| DC, absolute | 0.0144 | 0.0158 |
| SH rest, absolute | 0.015625 (= 1/64) | 0.015625 |

- Positions agree in sign on every axis, so the frame equals the source PLY
  frame. A Y/Z negation would have produced errors of the order of the scene
  extent.
- SH rest errors stay at exactly half a step. A channel-major versus
  Gaussian-major transpose would have produced errors of order 1, which
  confirms the channel-major ordering.
- The largest-component indices are spread evenly (about 2,000 per index), so
  all four reconstruction branches were exercised.

| File | Producer | N | SH | Chunk properties | Redistributable |

| engine `examples/assets/splats/guitar.compressed.ply` | SuperSplat 2.7.1 | 90,854 | 0 | 18 | No licence file beside it |
| engine `…/biker.compressed.ply` | SuperSplat 2.7.1 | 152,746 | 0 | 18 | No (header only inspected) |
| engine `…/hotel-culpture.compressed.ply` | SuperSplat 2.9.0 | 1,021,039 | 0 | 18 | No (header only inspected) |
| engine `…/skull.compressed.ply` | SuperSplat 2.6.1 | 246,821 | 3 | 18 | No licence file beside it |

The engine repository ships licence notes (`*.txt`) beside some of its other
splat assets but not beside these four, so they serve only as local
evidence. `guitar` and `skull` were decoded in full:

- The body size matched the header exactly.
- The chunk count equals `ceil(N / 256)`, and every chunk bound is finite with
  `min ≤ max`.
- Every decoded attribute is finite.
- `skull` reaches the writer's `−20` log-scale clamp.
- Colour bounds fall outside `[0, 1]` in every file (as low as −0.49 and as
  high as 2.61), so a decoder must not assume unit colour bounds.

Every producer version observed (SuperSplat 2.6.1, 2.7.1, and 2.9.0, and
SplatTransform 3.11.2) writes the 18-property chunk.

## 7. Proposed scope

- **In scope.** Binary little-endian. The 18-property `chunk`. Exactly the
  four packed `uint` vertex properties. An optional `sh` element with 9, 24,
  or 45 `uchar` columns. Full and metadata-only reads. Count and SH degree come
  from the header alone.
- **Rejected with specific `GSPLY` diagnostics.** The 12-property chunk, as an
  unsupported variant, until a real producer is found. ASCII or big-endian
  encodings. Inconsistent chunk or `sh` row counts. Unexpected property types.
  Non-finite or inverted chunk bounds. A truncated body. New codes follow
  `GSPLY-E019`.
- **Open for FMT-03.** Whether `SplatRenderMode: mip` should warn, by analogy
  with SPZ's antialiased flag (`GSPZ-W002`). The source-format label recorded
  in `customData.gs` and in the import stats.
- **Fixtures.** Commit both CC0 conversions with provenance, as the SOG corpus
  does. Extend `tools/generate_equivalence_fixtures.py` with an in-repo
  encoder that preserves source order, so the equivalence suite can compare by
  index at per-chunk tolerances from §4.
- **Package impact.** The change stays inside the existing `gaussian-ply`
  binary. It adds no new library, extension, or registration.

## 8. Other candidates

SPZ v4 was not spiked. It needs a vendored Zstandard decoder and a second SPZ
reader path ([SPZ_FORMAT.md §3](../reference/SPZ_FORMAT.md#3-container-version-scope)),
which brings an ADR, a licence review, and package changes on every target.
`.splat` and `.ksplat` were not spiked either. FMT-02 records their
disposition in the [backlog](../roadmap/backlog.md).

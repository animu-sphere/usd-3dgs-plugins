# v0.11.0 — SPZ v4 format coverage

- **Tag** `v0.11.0`
- **Commit** `f92861f707e510c18639da9d6be6391800cb3518`
- **Published** 2026-11-18 JST
- **GitHub** [v0.11.0 release](https://github.com/animu-sphere/usd-3dgs-plugins/releases/tag/v0.11.0)

The release reads SPZ version 4 through the existing `gaussian-spz` bundle.
Version 4 replaces the single gzip stream of v1-v3 with one Zstandard stream
per attribute class. A vendored, decompression-only Zstandard 1.5.7
([ADR 0002](https://github.com/animu-sphere/usd-3dgs-plugins/blob/v0.11.0/docs/adr/0002-vendored-zstd-decoder.md))
inflates each stream, and the attribute bytes are decoded exactly as
version 3 and authored through the shared layer writer. Files from current
SPZ writers no longer fail with `GSPZ-E003`, which now applies only to
versions above 4. A file whose `SPZ_ADOBE_coordinate_system` extension
declares a frame other than RUB is refused with the new `GSPZ-E016` in every
container version; v0.10.0 imported it in the wrong orientation.

## Decisions

- A declared non-RUB storage frame fails with `GSPZ-E016` in v1-v4 rather
  than importing mis-oriented with `GSPZ-W001`. Non-zero v4 reserved bytes
  are accepted, as the reference reader does. A gzip-wrapped header that
  claims version 4 is malformed (`GSPZ-E004`).
- SplatTransform 3.x writes RDF data without declaring it. Nothing in the
  file identifies such output, so it imports without a warning
  ([SPZ format §5](../reference/SPZ_FORMAT.md#undeclared-frame-splattransform-3x)).
- The vendored miniz, libwebp, and Zstandard symbols are hidden in the
  Linux and macOS libraries, and a shared exported-symbol check enforces it.
  v0.10.0 exported 40 miniz symbols from `gaussian-spz` and 319 libwebp and
  miniz symbols from `gaussian-sog`.
- Every packaged `THIRD_PARTY_NOTICES.md` carries the full licence text of
  each vendored component it covers; `tests/docs/test_notices.py` enforces
  this.

## Known limitations

- An SPZ file that declares a non-RUB frame no longer opens; convert it to
  RUB first.
- SPZ v4 is covered by synthetic and reference-written fixtures only; a v4
  corpus asset converted from the CC0 PLY corpus is still wanted.
- glTF `KHR_gaussian_splatting`, `.splat`, and `.ksplat` are not supported;
  glTF is the [v0.12.0 candidate](../roadmap/current.md) and the
  [backlog](../roadmap/backlog.md#other-format-candidates) records the others.

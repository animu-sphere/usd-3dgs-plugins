# v0.10.0 — Format coverage expansion

- **Tag** `v0.10.0`
- **Commit** `d3f00677d95b97caa39cf9cd8aeacc3e445aad3c`
- **Published** 2026-11-17 JST
- **GitHub** [v0.10.0 release](https://github.com/animu-sphere/usd-3dgs-plugins/releases/tag/v0.10.0)

The release adds SuperSplat compressed PLY to the `gaussian-ply` bundle. A
`.ply` whose header declares `packed_position` beside a `chunk` element is
routed to a compressed-PLY decoder and authored through the shared layer
writer; Graphdeco PLY routing and diagnostics are unchanged. Binary
little-endian files with the 18-property `chunk` and SH degrees 0-3 are
supported. ASCII and big-endian encodings and the colourless 12-property
`chunk` are rejected with specific diagnostics. The stage records
`sourceFormat = "Gaussian Splatting compressed PLY"`, and the
[mapping contract](https://github.com/animu-sphere/usd-3dgs-plugins/blob/v0.10.0/docs/reference/COMPRESSED_PLY_MAPPING.md)
states the quantization loss.

## Decisions

- Non-default render-mode tags (`SplatRenderMode: mip | 2dgs`,
  `postshot.anti_aliasing=1`) in a compressed PLY produce warning
  `GSPLY-W004`; the Gaussians are authored as ordinary 3DGS splats. Whether
  the uncompressed dialect should warn too is a backlog item.
- Compressed PLY records its own source-format label so consumers can tell a
  quantized source apart. Uncompressed PLY keeps `"Gaussian Splatting PLY"`.

## Known limitations

- SPZ version 4 is still rejected (`GSPZ-E003`); it is the
  [v0.11.0 candidate](../roadmap/current.md).
- `.splat`, `.ksplat`, and the 12-property compressed `chunk` are not
  supported; the [backlog](../roadmap/backlog.md#other-format-candidates)
  records revisit conditions.

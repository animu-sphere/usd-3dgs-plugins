## Changes

- Benchmark reports include container read, semantic decode, and USD authoring
  times. Before the PLY changes, container read took 88–89% of stage-open time
  on the near-ceiling asset, Garden, and Bicycle.
  [Phase baseline](../reference/BENCHMARK_CORPUS.md#v070-phase-baseline)
- `gaussian-ply` uses tinyPLY 3.0 with local fixes for property lookup, element
  counts, and skipped lists. The reader checks the minimum payload size before
  allocating vertex columns.
  [Third-party notice](../../THIRD_PARTY_NOTICES.md#tinyply-30)
- In Windows Release, opening the 7,995,392-Gaussian PLY took 5.84 seconds,
  compared with 13.83 seconds on the single-pass tinyPLY 2.3.4 build. Peak
  resident memory increased from 3.26 to 3.58 GiB and stayed within budget. Nine
  PLY assets passed the corpus targets and produced byte-identical flattened
  USDC against the v0.7.0 phase baseline.
  [Benchmark results](../reference/BENCHMARK_CORPUS.md#vendored-tinyply-30-verification)

## Compatibility

The binaries target OpenUSD 26.08 and Python 3.13 and must match the host ABI.
Import is read-only. Opening a Gaussian asset as a root layer synchronously
authors the full arrays. USD payload loading can defer import of the entire
asset. Drawing splats requires a compatible Hydra delegate.
[Supported configurations](../reference/SUPPORTED_CONFIGURATIONS.md) ·
[Interruption and lazy access](../reference/BENCHMARK_CORPUS.md#ply-interruption-and-lazy-access)

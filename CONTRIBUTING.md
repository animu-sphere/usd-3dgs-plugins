# Contributing

## Minimal development path

Everything needed to make and verify a change:

```sh
git clone https://github.com/animu-sphere/usd-3dgs-plugins
cd usd-3dgs-plugins
ost runtime pull cy2026 --profile usd     # once
ost plugin build plugins/gaussian-ply     # build
ost plugin test plugins/gaussian-ply --up-to 5   # the gate PRs must pass
```

CI covers Windows, macOS arm64, and Linux as declared in
`openstrata.ci.yaml`. Without `ost`, use the plain CMake path in the
[build guide](docs/guides/BUILDING.md) and consult the
[supported configurations](docs/reference/SUPPORTED_CONFIGURATIONS.md).

Check C/C++ formatting before opening a change. The repository uses the root
`.clang-format` policy and skips generated, vendored, and build output:

```sh
python scripts/check_clang_format.py --changed
python scripts/check_clang_format.py --all
python scripts/check_clang_format.py --all --write
```

The first command is the pull-request check; the second audits every tracked
first-party C/C++ file; the third applies the policy. Install `clang-format`
from the LLVM package for the host platform before running these commands.

Fast iteration on the decoder alone (no USD, no plugin reload):

```sh
ctest --test-dir plugins/gaussian-ply/build/cy2026-windows-x86_64-py313-usd --output-on-failure
```

## Where things go

| Change | Where |
| --- | --- |
| Parsing / semantics | `plugins/gaussian-ply/src/io/` (USD-free; unit-tested in `tests/test_gaussian_ply_decoder.cpp`) |
| USD authoring | `libs/gaussian-usd/` — shared by every format bundle (unit-tested in its own `tests/`, integration-tested in `plugins/gaussian-ply/tests/test_gaussian_ply_plugin.py`) |
| Format-independent model | `libs/gaussian-core/` (own version; bump only on its API changes) |
| Test inputs | `plugins/gaussian-ply/tests/fixtures/` — ASCII fixtures are committed text; binary ones are generated by `tools/generate_fixtures.py` and must end in `-binary-le` (a `.gitattributes` rule keeps them binary) |
| New diagnostics | add the code in `src/io/GaussianPlyDiagnostics.h` **and** the catalog `plugin/resources/gaussian-ply/diagnostics.json`; codes are never renumbered or reused |
| Behavior claims | `docs/reference/` (capability matrix, PLY mapping, dialects) — a claim without a fixture is a bug |

## Adding a new format

Adding a decoder follows one
end-to-end path:
[docs/contributing/ADDING_A_FORMAT_DECODER.md](docs/contributing/ADDING_A_FORMAT_DECODER.md).
It generalizes the PLY-specific loop above to the shared
`GaussianCloudData` contract, the reader/decoder/diagnostics split, and the
one shared writer — followable without reading PLY or SPZ source. The header
tiers it builds against are in
[docs/architecture/API_BOUNDARY.md](docs/architecture/API_BOUNDARY.md).

## Ground rules

- Follow [docs/design/DESIGN_POLICY.md](docs/design/DESIGN_POLICY.md); the
  [docs index](docs/README.md) explains which document owns which question.
- Every behavior change lands with a deterministic test; malformed input gets
  a fixture and a stable diagnostic.
- No external trained asset enters the repository without license and
  provenance review (design policy §17).
- Public Markdown is English; keep links relative and resolving.
- Release versions are single-sourced: `python scripts/release.py set-version
  X.Y.Z` — never hand-edit the version in individual files
  (`release.py guard` fails the release lane on drift).

## Documentation review

Review these sources when changing the corresponding behavior:

| Change | Review |
| --- | --- |
| Reader, decoder, or diagnostics | [Capability matrix](docs/reference/CAPABILITY_MATRIX.md), format specification and mapping, [diagnostics](docs/reference/DIAGNOSTICS.md), and fixtures |
| Shared model or validation | [Model contract](docs/reference/GAUSSIAN_MODEL_CONTRACT.md), equivalence tests, and an [ADR](docs/adr/) if a decision changes |
| USD authoring | [Stage contract](docs/architecture/WORKSPACE.md#5-authored-stage-contract), mappings, stage assertions, and migration impact |
| CI, packaging, or release tooling | [Supported configurations](docs/reference/SUPPORTED_CONFIGURATIONS.md), [install guide](docs/guides/INSTALL.md), and [release gate](docs/releases/README.md#release-gate) |
| New bundle | [Decoder guide](docs/contributing/ADDING_A_FORMAT_DECODER.md), bundle README, and the root README's short format summary |
| Milestone scope or status | [Release plan](docs/roadmap/release-plan.md), [current work](docs/roadmap/current.md), and [backlog](docs/roadmap/backlog.md); each item has one home |
| Integrated runtime or rendering | Link to the Formation owner's verified configuration and evidence |

Run the checks used by the docs workflow:

```sh
python -m pip install -r scripts/docs-requirements.txt
python -m unittest discover -s tests/docs -v
python scripts/check_docs.py
```

The checker covers first-party links and common forms of roadmap drift.
Reviewers still verify that support claims match the implementation and tests.
